## Kriteria kepastian simpan status kartu belajar

`set_card_status` harus memvalidasi identitas/status, membuka transaksi terluar, membaca kartu beserta pelajaran/kursus terbit dengan lock, lalu memeriksa akses current read di dalam transaksi. Pemeriksaan akses awal controller tidak cukup untuk keputusan mutasi. Hentikan kegagalan baca/tulis/status; konfirmasikan COMMIT/ROLLBACK melalui runner bersama dan pulihkan debug. Upsert tetap milik peserta/kartu, status `learning`/`known`, pengiriman status sama tidak menambah jumlah review atau mengganti waktu review, perubahan status sah menambah satu review. Tidak ada XP, nilai resmi, debit kredit atau perubahan konten.

Controller memakai 303 setelah sukses terkonfirmasi, tanpa query sesudah COMMIT. Gagal transaksi memakai 503 terbedakan belum tersimpan/belum pasti, tanpa query ulang, flash sukses, form kartu atau skrip simpan. GET menuju bagian kartu pada materi dengan slug dari server serta beranda; jangan retry POST otomatis. Identitas invalid ditolak 400 dan kartu/pelajaran/akses tidak sesuai ditolak 403. Kegagalan preflight sebelum model dimulai tidak otomatis tercakup. Halaman pemulihan mengikuti komponen bersama dengan konteks kartu dan tema usia; jangan menyebut kartu sudah dikuasai jika penyimpanan belum pasti.

Sebelum centang: reproduksi COMMIT FALSE yang dilaporkan sukses; unit tiap boundary/read/write, current read dan nesting; controller 503 tanpa reread serta renderer tanpa mutasi; regresi HTTP perubahan/ulang status, akses, identitas, keluarga dan tampilan. Tulis batas antara recording fake, SQL nyata, intersepsi browser dan respons 503 produksi. Transaksi editor deck/kartu tetap pekerjaan terpisah.

Status 16 Oktober 2026: unit model 155 dan controller/view kartu 46 assertion pada tiga runtime lulus; regresi HTTP kartu/progres, 12 kombinasi komponen pemulihan dan 12 publik lulus, tiga capture ditinjau. ## Kriteria kepastian penyimpanan progres baca

Verifikasi lanjutan database: gunakan pelajaran kedua fixture `progress-check` yang tepat, nonpratinjau/berbayar dengan entitlement aktif dan progres peserta utama awalnya kosong. Uji dua operasi pada tiga baseline (kosong, berjalan, selesai), dengan FALSE/exception pada BEGIN, baca pelajaran/akses, upsert, status sebelum/sesudah tulis, COMMIT dan ROLLBACK. Proxy tidak boleh meneruskan COMMIT injeksi meskipun target fault meleset; bandingkan digest seluruh baris 33 tabel sebelum/sesudah tiap kasus dan larang query sesudah gagal. Dua operasi penyiapan baseline boleh COMMIT terpisah, lalu hanya progres fixture tepat itu dibersihkan. Rollback oleh harness saat simulasi rollback gagal harus dibedakan dari kemampuan model. Helper hanya CLI development/PHP 8.1/database lokal, tidak memakai worker atau memutus koneksi nyata. Jangan mengubah angka bukti historis sebelum hasil aktual tersedia.

Simpan posisi baca dan tandai pelajaran selesai harus mengonfirmasi transaksi, bukan hanya status query sebelum COMMIT. Gunakan runner bersama dengan transaksi terluar; periksa BEGIN, baca pelajaran terkunci, akses current read, penulisan, status, COMMIT dan ROLLBACK. Hentikan kegagalan pertama, pulihkan debug, pertahankan upsert idempoten serta status selesai yang tidak bisa turun. Posisi tetap integer 0–10000; tidak menambah XP, penilaian atau mutasi ke tabel lain.

Kegagalan layanan setelah model dimulai memberi 503 (belum tersimpan atau belum pasti), tanpa reread DB, flash sukses atau form mutasi. Respons AJAX tidak mengaku sukses/merotasi token untuk retry; browser menghentikan antrean dan autosave sampai GET manual memuat keadaan terbaru. Kegagalan transport/JSON juga menghentikan pengiriman lanjutan dari DOM lama. Tombol manual tidak boleh melewati penguncian ini atau balapan dengan autosave berjalan. Sukses yang terkonfirmasi mempertahankan rotasi CSRF AJAX dan memakai redirect 303 untuk POST HTML. Akses dicabut tetap penolakan domain, bukan sukses palsu. Halaman pemulihan mengikuti komponen/tema bersama dengan konteks progres baca dan tautan GET materi serta beranda.

Sebelum centang: reproduksi COMMIT FALSE yang dilaporkan sukses; unit model FALSE/exception pada boundary/query, status selesai/upsert, domain, current read dan nesting; controller tanpa query setelah kegagalan; renderer escaping/tautan; JavaScript antrean, timeout respons, kegagalan/JSON dan submit manual; regresi HTTP progres/akses/keluarga. Bukti unit tidak menggantikan kegagalan koneksi database nyata, race paralel atau pemeriksaan Ubuntu/PHP-FPM. Kegagalan preflight akun/controller tetap di luar cakupan. Catat hasil yang benar-benar dijalankan, jangan centang seluruh progres atau roadmap dari perbaikan ini saja.

## Kriteria kepastian penyimpanan permainan

Mulai, memilih pasangan, dan menghentikan permainan tersimpan harus memakai kepemilikan transaksi terluar serta pemeriksaan BEGIN/baca/tulis/status/COMMIT/ROLLBACK yang sama dengan latihan. Reproduksi dulu hasil sukses palsu ketika COMMIT FALSE. Hentikan operasi pada kegagalan pertama, periksa ID insert, JSON dan audit; pulihkan debug. Jangan mengubah aturan `matching_v1`, snapshot, jumlah pasangan usia, urutan lock, revisi, key replay, batas langkah, hak melihat histori atau izin menghentikan permainan setelah akses materi dicabut. Pembacaan awal yang dipindahkan ke dalam transaksi tidak boleh membuat replay/hak mutasi memakai snapshot usang sesudah menunggu lock; gunakan current read pada data tersebut.

Respons kegagalan transaksi memakai 503: belum berhasil disimpan bila belum dimulai/rollback terkonfirmasi, dan belum dapat dipastikan bila COMMIT/ROLLBACK tidak terkonfirmasi. Pada cabang ini jangan baca ulang DB, buat token/form permainan, pasang skrip simpan, atau tampilkan flash/progres lama seolah terbaru. Sediakan GET periksa keadaan terbaru (intro untuk mulai, halaman run untuk pilihan/berhenti) dan riwayat; jangan retry POST otomatis. Reuse komponen pemulihan bersama latihan dengan judul/petunjuk permainan, tetap mengikuti tema usia. Sukses hanya 303 sesudah commit terkonfirmasi; 400/403/404/409 mempertahankan aturan yang ada. Jalur JavaScript harus menangani 503 tanpa menyatakan gagal pasti atau memberi skor optimistis.

Sebelum centang: unit FALSE/exception di setiap tahap, domain/replay, kepemilikan/debug, tidak ada operasi sesudah gagal, current-read SQL, controller/view tanpa reread/flash/form, serta 503 pada JavaScript. Uji rollback melalui fixture sintetis unik pada database nyata tanpa meneruskan COMMIT injeksi; bandingkan digest baris terkait dan bersihkan hanya data uji. Jalankan regresi normal start/move/final/stop, batas akses, snapshot, histori dan tampilan 360/768/1280. Uji tersebut tidak membuktikan putus jaringan sesudah COMMIT nyata, race paralel atau Linux; worker resilience/server baru tidak dijalankan pada putaran ini. Status dan bukti dicatat setelah hasil tersedia, bukan diasumsikan selesai.

Status 16 Oktober 2026: implementasi lokal lulus unit transaksi 833, controller 183 dan view 79 assertion pada tiga runtime, 49 injeksi database pada 19 tabel, regresi normal HTTP/browser 39 kombinasi serta 24 komponen permainan/latihan. Tiga capture ditinjau, regresi latihan/keluarga/progres/flashcard dan smoke/lint 357 PHP lulus; fixture dibersihkan. ## Kriteria kepastian penyimpanan latihan

Mulai latihan kursus/keluarga serta simpan/final jawaban harus memeriksa keberhasilan BEGIN, query baca/tulis, status transaksi, COMMIT dan ROLLBACK. Jangan mengembalikan sukses hanya karena belum ada query yang gagal: COMMIT juga harus dikonfirmasi. Hentikan operasi setelah kegagalan pertama. Gunakan pembungkus transaksi bersama untuk operasi ini; pertahankan urutan lock, snapshot, nilai, hak akses, revisi dan idempotensi yang sudah ada.

Pembungkus harus memiliki transaksi terluar; tolak transaksi bertingkat tanpa mengambil alih transaksi pemanggil. Pemeriksaan akses mutasi sesudah menunggu lock harus memakai current read, bukan snapshot yang terbentuk dari pembacaan awal. Jalur baca biasa tetap tidak meminta lock mutasi. Cakupan awal hanya mulai latihan kursus, mulai attempt keluarga, dan simpan/final jawaban; transaksi penyusunan/kirim/salin/batal keluarga serta model lain tidak otomatis dianggap sudah diperkuat.

Bedakan penolakan domain yang berhasil di-rollback (400/403/404/409), layanan belum tersedia dengan perubahan dibatalkan atau belum dimulai (503), dan hasil belum pasti karena COMMIT/ROLLBACK tidak terkonfirmasi (503). Pada hasil belum pasti jangan mengklaim data pasti tersimpan, pasti hilang, atau pasti dibatalkan. Peserta diarahkan ke tautan GET untuk memeriksa keadaan terbaru, bukan tombol retry POST atau pengiriman ulang otomatis. Halaman pemulihan tidak boleh membaca ulang DB pada permintaan POST yang baru gagal; jangan tampilkan form jawaban atau nilai yang dapat disangka kondisi terbaru. Setelah COMMIT berhasil, gunakan status hasil operasi untuk pesan sukses, tanpa query tambahan yang dapat gagal sesudah perubahan sudah tersimpan.

Matikan tampilan debug DB hanya selama pembungkus berjalan dan pulihkan nilai semula pada semua jalur. Diagnostik baru bersifat generik tanpa teks soal/jawaban/token; ini tidak menyatakan logger SQL bawaan CI3 sudah disanitasi. Uji BEGIN/COMMIT/ROLLBACK FALSE dan exception, kegagalan baca/tulis/audit/snapshot, penolakan domain, replay sukses, restore debug, tidak ada operasi lanjutan setelah kegagalan, pemisahan akun/keluarga, respons pemulihan tanpa query ulang, dan transaksi rollback dengan fixture sintetis. Uji injeksi bukan bukti putus jaringan setelah COMMIT nyata atau konkurensi staging. Tidak mengubah harga, kuota, jadwal, penilaian atau kebijakan konten.

Status 16 Oktober 2026: perbaikan lokal lulus tujuh unit pada tiga runtime (2.022 assertion/runtime), 54 injeksi kegagalan dalam transaksi database fixture tanpa COMMIT nyata, regresi kursus/keluarga/akses/progres dan smoke/lint 351 PHP. Browser memeriksa 45 kombinasi halaman, 12 komponen recovery dan 12 publik; tiga capture komponen ditinjau. Fixture dibersihkan, skema tidak berubah. ## Kriteria progres pada daftar isi kursus

Daftar isi kursus terbit menampilkan status pelajaran milik akun yang sedang masuk: **Belum dimulai**, **Sedang dipelajari**, atau **Selesai**. Ambil status dalam satu query terikat identitas sesi dan ID kursus, bukan query per baris. Hanya pelajaran/kursus terbit yang ikut; urutan bagian dan pelajaran tetap seperti indeks yang sudah ada. Orang tua yang membuka katalog melihat progres dirinya sendiri, bukan progres anak dari parameter URL. Pengunjung tanpa login tidak diberi status pribadi.

Untuk materi yang masih dapat dibaca, tombol peserta menjadi **Mulai belajar**, **Lanjutkan**, atau **Baca ulang** sesuai status. Lanjutkan memakai tautan GET yang sudah memulihkan posisi (`?lanjut=1#reading-material`), sedangkan baca ulang tidak menghapus progres selesai. Materi pratinjau tetap terbuka sesuai aturan lama. Materi terkunci tetap berlabel **Terkunci** dan tidak mendapat tautan baca walaupun ada histori progres milik peserta; status tersimpan tidak memberi akses baru. Keterangan menjelaskan bahwa ini progres akun sendiri, bukan nilai/kelulusan atau persentase penguasaan.

Jika query progres gagal, jangan melabeli semua materi belum dimulai. Tampilkan pesan progres belum dapat dimuat serta tautan muat ulang GET; tautan baca yang memang diizinkan tetap tersedia dengan label netral. Keadaan daftar pelajaran kosong tetap berbeda dari kegagalan progres. Halaman dengan akun masuk mengirim private/no-store/noindex; GET/HEAD tidak menulis progres, aktivitas belajar, enrollment atau audit konten. Tombol tetap native tanpa JavaScript, nama aksesibel menyertakan judul materi, dan susunan mobile tidak memotong judul panjang.

Uji penerimaan: kosong/berjalan/selesai/not_started eksplisit, dua peserta dan orang tua yang tertaut, pengunjung, filter identitas palsu pada query diabaikan, kursus/pelajaran draf/arsip, query gagal, urutan seri stabil, gratis/pratinjau/enrollment manual/free/paket aktif, waktu hak paket dan pencabutan, GET/HEAD tanpa mutasi, escaping/Unicode, nama tautan dan URL resume, viewport 360/768/1280. Tidak menambah skema, rekomendasi, keputusan kurikulum, definisi kelulusan kursus atau transaksi pembayaran.

## Kriteria peringatan jawaban latihan belum tersimpan

Pada pengerjaan latihan mandiri maupun sesi keluarga milik peserta yang tepat berstatus `in_progress`, gunakan komponen peringatan perubahan bersama. Tampilkan petunjuk bahwa pilihan tidak tersimpan otomatis dan tombol **Simpan sementara** harus dipakai sebelum beristirahat. Status perubahan baru muncul setelah skrip siap, diumumkan secara sopan, dan kembali bersih bila pilihan dikembalikan ke nilai dari server. Jangan menyimpan jawaban ke localStorage/sessionStorage, menambah autosave, endpoint, timer atau penilaian baru.

Meninggalkan halaman dengan perubahan memasang pengaman `beforeunload`; kemampuan browser menampilkan dialog tidak dijamin pada seluruh perangkat atau penutupan paksa. Pengiriman form native yang sah tidak memunculkan peringatan keluar, tetapi juga tidak boleh dianggap bukti jawaban sudah tersimpan. Pada respons 400/409, tampilkan pesan penolakan dan pilihan tersimpan yang dikirim ulang oleh server: jangan memulihkan POST yang ditolak atau menandai pilihan server sebagai belum tersimpan. Hasil final/laporan orang tua tidak mempunyai form atau pengaman perubahan. Status attempt selain `in_progress`/`graded` ditolak oleh pemeriksaan akses, tanpa mengubah histori.

Kriteria uji: pilihan radio dengan mouse/keyboard, kembali ke pilihan asal, nilai hidden bukan perubahan, navigasi dibatalkan/diteruskan, reset/history restore, submit biasa serta konflik 409/opsi asing 400, fallback tanpa JavaScript, tidak bocor kunci pada pengerjaan, hak keluarga/peran, tampilan 360/768/1280 dan tidak ada penulisan saat hanya mengubah pilihan di browser. Simpan/final tetap mengikuti transaksi/revisi/CSRF lama. Ini pengaman kehilangan isian saat navigasi biasa, bukan pemulihan offline, jaminan BFCache lintas browser atau autosave.

## Kriteria konsistensi tombol bertema

Tombol `.btn-primary`, `.btn-outline-primary`, dan `.btn-link` harus memakai token tema bersama pada keadaan normal, hover, aktif, fokus keyboard dan nonaktif. Berlaku pada layout peserta dengan Bootstrap maupun layout pengelola yang memuat Bootstrap lalu CoreUI; kedua namespace variabel komponen perlu dipetakan tanpa mengedit berkas vendor. Warna primer yang sudah ada dipertahankan. Teks tombol outline/link memakai warna primer gelap agar terbaca juga di permukaan pastel, bukan mengandalkan warna bawaan biru. Teks tombol isi tetap putih. Tombol bahaya/sukses dan arti status tidak diwarnai ulang menjadi warna merek.

Pertahankan semantik native, ukuran kontrol, susunan halaman, tautan/form/CSRF dan izin. Tombol `disabled` tetap tidak dapat diaktifkan; tautan nonaktif memerlukan `aria-disabled` dan pengelolaan fokus/perilaku, bukan warna saja. Focus ring yang sudah ada tetap terlihat; label pasangan `.btn-check` perlu indikator fokus yang jelas. Tidak menambah efek animasi atau memaksa palet dalam mode forced-colors.

Sebelum centang: reproduksi ketidaksesuaian awal, periksa computed style pada kedua susunan CSS dan seluruh palet, keadaan tombol/button-link/checkable, normal/hover/pressed/active/focus/disabled, ukuran 360/768/1280 px, serta kontras teks aktif minimal 4,5:1 dan indikator/batas relevan minimal 3:1 pada permukaan uji. Nilai ambang dibandingkan tanpa pembulatan. Uji komponen sintetis tidak menggantikan review halaman aktual, zoom atau UAT. Acuan: [W3C kontras teks](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) dan [kontras nonteks](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).

## Kriteria lanjut belajar dari dashboard

Dashboard peserta dewasa dan anak menampilkan paling banyak tiga pelajaran milik peserta yang berstatus `in_progress`, diurutkan menurut waktu penyimpanan progres terbaru lalu ID pelajaran menurun sebagai pemutus seri. Pelajaran dan kursus harus masih terbit. Terapkan hak yang sama dengan halaman materi sebelum pembatasan tiga hasil: kursus gratis, materi pratinjau, enrollment manual/free aktif, atau enrollment paket aktif dengan entitlement aktif yang sudah mulai dan belum habis. Tidak memberi akses baru, tidak mengaktifkan pembayaran dan tidak menghapus histori ketika akses berubah.

Setiap kartu menampilkan judul materi/kursus yang ter-escape, waktu progres terakhir disimpan, dan tautan native “Lanjutkan materi” menuju halaman materi yang sudah memulihkan posisi baca. Jangan menyebut waktu tersebut sebagai waktu terakhir membuka halaman, persentase penguasaan atau durasi belajar. Tidak ada autosave baru, penulisan progres saat dashboard dibuka, atau penyimpanan browser. Hak tetap diperiksa ulang saat peserta membuka tujuan.

Jika ada materi untuk dilanjutkan, tampilkan bagian ini sebagai langkah utama, bukan kartu kosong yang menyuruh mulai dari katalog. Jika tidak ada, pertahankan ajakan menjelajah katalog tanpa mengklaim bahwa histori terhapus. Kegagalan query bukan keadaan kosong: tampilkan pesan daftar lanjut belum dapat dimuat dan tautan muat ulang GET. Dashboard orang tua tetap mengutamakan keluarga; jangan tampilkan tautan pengerjaan atas nama anak. Tema usia yang sudah dipilih tetap diwarisi dari layout.

Uji sebelum menandai selesai: isolasi pengguna/anak, status selesai/belum mulai/draf/arsip, seluruh jalur akses dan waktu entitlement, lebih dari tiga kandidat dengan kandidat terbaru terkunci, tie-break timestamp, input pengalih identitas di query diabaikan, GET/HEAD tanpa mutasi progres, kegagalan query, escaping/Unicode, tujuan resume, serta tampilan anak/dewasa di 360/768/1280 px. Ini bukan daftar histori lengkap, rekomendasi berbasis AI, aturan penyelesaian kursus, atau bukti kesiapan produksi.

## Kriteria penolakan rollback yang berisiko menghapus data

Migration 001–008 harus memeriksa seluruh tabel yang akan dihapus atau kehilangan kolom sebelum menjalankan DDL pertama pada `down()`. Bila ada baris, query gagal, atau hasil COUNT tidak sah, hentikan dengan exception tanpa perubahan pada langkah tersebut. Kebijakan ini sengaja konservatif: empat peran awal di migration 003 juga dianggap data; tidak ada pengecualian seed atau penghapusan diam-diam. Migration 013 harus menggunakan validasi COUNT ketat yang sama, bukan cast yang mengubah nilai tidak sah menjadi nol. SQL `up()`, skema dan nomor migration tidak berubah.

Uji unit wajib mencakup setiap posisi pemeriksaan, hasil gagal/nonempty/malformed dan bukti tidak ada penulisan sebelum penolakan. Uji integrasi memakai skema sementara unik yang dibuat penguji, dibangun naik ke versi yang diperiksa, lalu mencoba tepat satu langkah turun dengan data sintetis. Bandingkan versi, seluruh isi tabel, dan `SHOW CREATE TABLE` sebelum/sesudah penolakan; database operasional `db_study` tidak boleh diturunkan. Keberhasilan pada tabel kosong diuji terpisah dan tidak boleh menjadi alasan menghapus data agar rollback operasional lolos.

Ini bukan transaksi DDL atomik, pengunci penulisan bersamaan, atau persetujuan downgrade beberapa versi. CI3 dapat menjalankan langkah terdahulu sebelum langkah berikutnya menolak, dan penanda versi pada kegagalan downgrade multi-langkah tidak cukup untuk menyimpulkan bentuk skema. Hentikan penulisan, buat cadangan terverifikasi, dan tinjau struktur aktual serta rencana pemulihan/perbaikan maju sebelum tindakan operasional. Bukti dan batas penerapan dicatat setelah pengujian selesai.

Unit 26 jalur dan 43 lokasi COUNT lulus pada tiga runtime; integrasi 18 skema sementara lulus dan seluruh skema uji dibersihkan. ## Kriteria perubahan kata sandi sendiri

Peserta, orang tua, anak dan pengelola yang sudah masuk boleh mengganti sandi akunnya sendiri dengan sandi lama, sandi baru dan konfirmasi. Tidak ada ID akun tujuan dalam formulir; ini bukan reset sandi anak oleh orang tua atau pemulihan lupa sandi. Minimum mengikuti pembuatan akun (anak 10, dewasa/orang tua 12, admin sistem 16 karakter), maksimum 72 byte. Sandi baru tidak boleh sama. POST ber-CSRF, pesan tertaut ke kontrol, semua field sandi selalu kosong saat form ditampilkan kembali, no-store/noindex dan tema akun berlaku.

Perubahan mengunci baris akun, memeriksa akun aktif serta versi kredensial sesi terkini, lalu memperbarui hash dan mencatat satu audit tanpa sandi/hash/token dalam transaksi. Sepuluh kegagalan verifikasi sandi lama per akun selama 15 menit menghentikan percobaan berikutnya; hitungan lintas perangkat dan tidak dihapus oleh keberhasilan. Format yang invalid tidak menjalankan pemeriksaan sandi. Sesi menyimpan HMAC terpisah atas ID/hash kredensial dengan kunci aplikasi, bukan hash sandi mentah. Setiap request terautentikasi membandingkan HMAC dengan keadaan DB; perubahan hash/kunci membuat sesi lama tidak berlaku pada request berikutnya. Request yang sudah berjalan tidak dijanjikan dibatalkan secara retroaktif.

Sesudah berhasil, autentikasi perangkat saat ini dihapus dan ID sesi dirotasi dengan ID lama dihancurkan; pengguna diminta masuk kembali. Perangkat lain ditolak pada request berikutnya. Penerapan pertama mewajibkan sesi lama yang belum punya penanda kredensial untuk masuk ulang. Tidak menghapus kemajuan belajar, keluarga atau transaksi. Uji wajib: valid/invalid/CSRF/metode, berbagai peran, isolasi akun, dua sesi dan stale submit/replay, pencabutan akun, throttle, atomisitas audit, tanpa rahasia dalam HTML/audit, dan viewport. Email pemberitahuan serta pemulihan akun tetap tahap terpisah. Pedoman keamanan: [OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html) dan [Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).

## Kriteria pengelolaan susunan kursus draf

Pengelola konten pemilik draf dan admin sistem dapat menambah bagian, mengubah judul/urutan bagian, serta memindahkan pelajaran ke bagian lain dalam kursus yang sama dan mengubah urutannya. Ini memakai tabel bagian/pelajaran yang sudah ada, bukan paket berbayar. Bagian kosong tetap boleh disiapkan; penghapusan bagian/pelajaran tidak termasuk perubahan ini. Nomor urut 1–9999, maksimal 100 bagian per kursus sebagai batas teknis editor, bukan kuota paket. Urutan sama dipecahkan stabil dengan ID bagian lalu ID pelajaran; tampilan katalog dan pelajaran berikutnya harus mengikuti urutan identik.

Semua perubahan hanya pada draf, diperiksa kembali dalam transaksi dengan lock kursus, akun/peran aktif dan kepemilikan. Form membawa versi kursus: form usang atau replay perubahan berhasil ditolak konflik tanpa menulis ulang. Perubahan sah menaikkan versi kursus; pemindahan pelajaran juga menaikkan versi pelajaran. Perubahan tanpa selisih tidak menulis audit/versi. Audit menyimpan aksi, ID dan perubahan urutan/versi, bukan isi materi atau data anak. Gagal menulis audit harus membatalkan seluruh perubahan. Kursus review/terbit/arsip tidak dapat disusun ulang; snapshot jawaban, progres, slug, isi materi dan akses tidak diubah.

Halaman menggunakan form biasa tanpa drag-and-drop atau JavaScript wajib, pilihan bagian berurutan, pesan validasi, konfirmasi hasil dan pagination pelajaran 10 per halaman. Pilihan bagian dan halaman dipertahankan oleh form, pagination, muat ulang, serta redirect setelah simpan; hanya ID bagian dalam kursus dan halaman yang sudah dibatasi server boleh masuk URL. Pelajaran yang dipindahkan dapat muncul di halaman lain sesuai urutan barunya. Kiriman bagian asing meminta pengguna memilih kembali, tidak diam-diam menarget bagian pertama. Uji kepemilikan/peran, akun nonaktif, kursus/section/lesson asing, input array/negatif/ekstrem/Unicode, revisi usang/replay, no-op, batas bagian, rollback audit, urutan stabil dan urutan materi berikutnya. Fitur belum dianggap aktif sebelum route/UI serta tes HTTP/browser tersedia.

Penambahan dan perubahan materi pelajaran juga menaikkan versi kursus dalam transaksi yang sama dengan data dan audit, sehingga form susunan lama harus dimuat ulang. Editor materi membawa versi pelajaran yang dilihat saat form dibuka; tab usang/replay mendapat HTTP 409, tanpa menimpa data atau menambah audit. Nilai aman yang diketik tetap terlihat agar dapat disalin sebelum muat ulang, tetapi tombol simpan dinonaktifkan. Pemindahan pelajaran membatalkan form materi lama melalui kenaikan versi pelajaran. Ini belum merupakan autosave, penggabungan otomatis, atau perlindungan konflik pada seluruh editor aplikasi.

Model susunan menangani gagal memulai transaksi, query baca/tulis, audit dan exception dengan hasil gagal serta rollback eksplisit bila transaksi sudah dimulai; pengaturan debug database dipulihkan. Bila rollback atau COMMIT gagal atau hasilnya tidak diketahui, jangan menjanjikan bahwa tidak ada perubahan: tampilkan status penyimpanan belum pasti, nonaktifkan form lama dan minta muat ulang untuk memeriksa hasil. Tidak ada retry POST otomatis. Pengujian kegagalan sebelum COMMIT tidak membuktikan perilaku putus jaringan sesudah server menerima COMMIT.

Halaman mengambil data daftar sebelum mutasi dan tidak membaca model lagi setelah hasil mutasi diterima. Pada respons 503, daftar diberi penjelasan bahwa isinya adalah keadaan sebelum upaya simpan, bukan bukti keadaan database terbaru; formulir dinonaktifkan sampai GET baru. Setelah sukses, redirect lokal memakai konteks asal yang sudah divalidasi dan GET tujuan memuat ulang data serta membatasi halaman.

## Kriteria gambar pendamping pelajaran — implementasi lokal, verifikasi belum lengkap

Satu pelajaran boleh mempunyai satu gambar pendamping PNG/JPEG, tanpa menggantikan teks materi. Pengelola pemilik draf/admin sistem dapat menambah, mengganti, mengubah keterangan, atau melepas gambar. Teks alternatif 3–300 karakter, keterangan opsional sampai 1.000 karakter, sumber 5–2.000 karakter, dan status hak penggunaan wajib. Reviewer memeriksa gambar beserta materi sebelum terbit. Perubahan membawa versi pelajaran dan menaikkan versi pelajaran/kursus bersama audit; form usang tidak menimpa gambar terbaru. Gambar tidak dapat diubah saat kursus review, terbit atau arsip.

Batas teknis awal: unggahan 3 MiB, sisi maksimal 4.096 piksel, total maksimal 4 juta piksel, hasil normalisasi maksimal 6 MiB. Ekstensi dan MIME harus cocok, berkas harus benar-benar unggahan PHP, kemudian didekode dan dienkode ulang. Nama fisik acak; nama asli, metadata EXIF, dan payload tambahan tidak digunakan. SVG, GIF, PDF, video, URL gambar jarak jauh, editor HTML, serta gambar soal belum termasuk fitur ini. GD/fileinfo wajib untuk unggah; bila tidak tersedia, unggahan gagal tertutup. Gambar tersimpan yang valid tetap dapat dibaca tanpa GD.

Berkas disimpan di direktori privat di luar document root, bukan URL file publik. Endpoint peserta memeriksa hak pelajaran pada setiap GET/HEAD; endpoint pratinjau terpisah mengikuti izin pengelola. Respons memakai MIME tetap, nosniff dan private/no-store. Melepas gambar tidak menghapus materi/progres. Berkas baru ditulis sebelum transaksi DB; berkas lama tidak dihapus sebelum commit dikonfirmasi. Kegagalan atau hasil transaksi yang belum pasti tidak boleh menghapus berkas yang mungkin sudah direferensikan. Orphan akibat crash/hasil belum pasti harus direkonsiliasi secara terkontrol; backup DB saja tidak cukup untuk memulihkan media.

Kriteria penerimaan: PNG/JPEG valid, manipulasi MIME/ekstensi/nama, berkas rusak/terlalu besar/dimensi ekstrem, array fields, CSRF, hak lintas akun/kursus/status, revisi/replay/no-op, rollback audit, filesystem gagal, publikasi dengan berkas hilang, akses gratis/pratinjau/berbayar/revokasi/arsip, GET/HEAD/405, escaping, dan ponsel/tablet/desktop. Uji HTTP unggah sukses PHP 8.1 tetap wajib sebelum fitur dianggap terverifikasi penuh; lingkungan saat ini hanya menyediakan GD pada CLI 8.1, bukan Apache 8.0. Rujukan rancangan: [OWASP File Upload](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html), [dekode gambar PHP](https://www.php.net/manual/en/function.imagecreatefromstring.php), dan [pemeriksaan unggahan asli PHP](https://www.php.net/manual/en/function.is-uploaded-file.php).

Status 15 Oktober 2026: migration 13, model transaksi, editor gambar, pratinjau reviewer dan endpoint peserta sudah tersedia. Uji normalisasi CLI, metadata/pelepasan melalui HTTP, otorisasi serta gerbang berkas hilang/rusak, 18 probe kegagalan transaksi, dan enam kombinasi route/viewport lulus. [Bukti tampilan dan batas pengujian](visual-baseline/2026-10-15-lesson-media/README.md) tidak menutup unggah multipart sukses PHP 8.1, uji Ubuntu atau rekonsiliasi orphan. Latihan restore DB+berkas terisolasi kemudian lulus sebagaimana dicatat di bawah; pemulihan operasional tetap belum terbukti. Tidak ada media nyata/berlisensi yang diterbitkan dari fixture ini.

## Default implementasi latihan mandiri — 15 Oktober 2026

Ini keputusan implementasi sementara oleh pengembang dalam lingkup instruksi menjalankan roadmap, bukan klaim persetujuan produk atas harga, kurikulum, atau rilis. Mesin latihan generik tidak memerlukan pilihan jenjang konten terlebih dahulu. Konten nyata tetap ditulis dan ditinjau dua pengelola sebelum terbit.

- Latihan berada pada kursus: maksimal 50 soal pilihan ganda, empat pilihan dan satu jawaban benar per soal. Soal mengikuti draf/review/publikasi kursus, wajib memiliki pembahasan serta sumber/hak penggunaan.
- Semua soal berbobot satu. Tampilkan jumlah benar dan persentase dua desimal (pembulatan half-up), tanpa kelulusan, peringkat, XP, atau kredit. Jawaban kosong dihitung tidak benar saat diselesaikan.
- Peserta dapat mengulang; setiap percobaan selesai tetap tersimpan. Satu percobaan aktif per peserta/kursus, tanpa timer. Tombol mulai yang dikirim ulang mengarah ke percobaan yang sama; tombol mulai baru setelah selesai membuat histori baru.
- Simpan salinan soal, pilihan, kunci, pembahasan, dan versi pada awal percobaan. Kunci/pembahasan hanya ditampilkan setelah submit final. Simpan sementara dapat dilanjutkan; revisi jawaban mencegah tab lama menimpa jawaban terbaru. Submit final berulang tidak menggandakan nilai.
- Peserta hanya melihat percobaannya sendiri. Latihan mewarisi hak akses kursus dan memeriksa ulang hak saat menyimpan/menyelesaikan. Hasil yang sudah selesai tetap merupakan histori pribadi; percobaan aktif tidak dapat diteruskan setelah hak kursus dicabut.
- Untuk pendampingan, orang tua yang terhubung aktif mempunyai laporan baca-saja terpisah: jumlah percobaan selesai/berjalan, hasil tiap percobaan, dan pembahasan sesudah final. Orang tua tidak dapat membuka jawaban aktif, mengganti jawaban, atau menyelesaikan percobaan anak. Akses laporan hilang saat hubungan dicabut atau akun anak tidak aktif, termasuk pada URL yang pernah dibuka. Hasil selesai dari kursus yang diarsipkan tetap terlihat selama hubungan aktif. Laporan ini tidak mengubah aturan sesi khusus/premium.
- Sesi khusus orang tua, kuota premium, soal privat anak, penilaian manual, dan ujian bersertifikat tetap tahap tersendiri. Default di atas tidak otomatis menentukan aturan fitur tersebut.

### Default sementara penyusun latihan keluarga — 15 Oktober 2026

Implementasi bertahap mengikuti permintaan awal soal buatan orang tua. Alur saat ini meliputi draf, pengiriman terjadwal, satu percobaan anak, dan hasil privat; ini belum mencakup semua variasi sesi keluarga:

- Mulai dari soal tulisan sendiri berupa empat pilihan unik, satu kunci, pembahasan, sumber, dan hak penggunaan. Pemilihan dari bank umum serta jenis soal lain menyusul.
- Satu sesi punya satu pembuat dan satu anak tujuan; anak tujuan tidak dapat diganti setelah pembuatan. Orang tua lain, termasuk yang tertaut ke anak sama, tidak dapat membaca atau mengubah draf pembuat. Anak juga belum dapat membuka draf.
- Batas teknis sementara: 50 soal per sesi dan 100 sesi berstatus draf per pembuat. Ini pagar teknis lokal, bukan penetapan kuota/harga komersial. Pembatalan mengubah status dan mempertahankan riwayat.
- Hak menulis memakai entitlement milik orang tua yang masih aktif dan sudah mulai/belum berakhir, pada paket dengan `family_practice_enabled=1`. Semua paket lama/baru default-nya 0; memiliki paket biasa atau saldo kredit saja tidak cukup. Belum ada UI jual/beli atau pemberian hak paket. Pengujian memakai entitlement sintetis yang dibersihkan, bukan akses gratis tersembunyi atau pembayaran riil.
- Paket yang diarsipkan untuk penjualan tidak otomatis mencabut entitlement yang masih berlaku; pencabutan melalui status entitlement atau kapabilitas paket. Draf dapat dibaca setelah hak paket habis, tetapi tidak diedit; pembuat masih boleh membatalkan. Hubungan keluarga yang dicabut atau akun anak nonaktif menutup baca maupun tulis.
- Pembuatan memakai token bertanda tangan dan pengiriman ulang tidak membuat sesi ganda. Revisi draf menolak perubahan dari tab usang; setiap perubahan penting dicatat tanpa teks soal privat di audit.
- Saat kirim, soal divalidasi dan disalin menjadi snapshot; judul/anak/soal/jadwal tidak dapat diubah sesudah dikirim. Waktu diisi dalam WIB dan disimpan UTC. Mulai boleh langsung atau terjadwal, batas akhir wajib setelah mulai dan maksimal 90 hari dari saat kirim. Tidak ada hitung mundur atau notifikasi otomatis.
- Satu sesi memberi satu percobaan anak, tanpa batas waktu per soal. Mengulang membutuhkan sesi baru. Mulai dan finalisasi ulang tidak menggandakan percobaan/nilai. Bobot dan pembulatan sama dengan latihan mandiri; jawaban sementara dapat dilanjutkan sebelum batas akhir.
- Default sementara memakai pemeriksaan hak paket orang tua pada kirim, mulai, dan setiap simpan/final. Jadwal lewat, hak paket dicabut/habis, atau hubungan keluarga tidak aktif menghentikan pengerjaan tanpa menghapus jawaban tersimpan. Pemulihan hak sebelum deadline memungkinkan lanjut. Aturan ini harus ditinjau lagi sebelum pilot komersial; bukan janji masa akses tambahan.
- Pembuat boleh membatalkan sesi tersedia/berjalan meski hak paket habis; attempt berjalan menjadi `abandoned`, jawaban/snapshot dipertahankan tanpa nilai final. Sesi selesai tidak bisa dibatalkan. Riwayat selesai milik anak tetap dapat dibaca anak setelah hak paket atau tautan berubah; orang tua pembuat harus tetap mempunyai tautan aktif untuk melihat hasil. Orang tua kedua dari anak sama tidak dapat membuka hasil sesi privat milik pembuat lain.
- Pemilihan bank soal, jenis selain pilihan ganda, pengaturan kuota/harga, notifikasi dan analisis per topik tetap pengembangan lanjut. Penyalinan sesi mengikuti kriteria tersendiri di bawah. Pilihan ini tidak mengubah keputusan harga, Midtrans, atau kebijakan rilis publik.

### Kriteria salin sesi keluarga — 15 Oktober 2026

Orang tua pembuat dengan hak penyusun aktif dapat menyalin sesi miliknya ke draf baru untuk anak yang sama atau anak lain yang tertaut aktif. Sumber tetap memerlukan hubungan aktif; tidak ada akses ke sesi orang tua lain meski anaknya sama. Formulir menyebut sesi sumber, anak tujuan dan nama baru, serta meminta konfirmasi. Draf kosong/tidak lengkap ditolak. Batas 50 soal per sesi dan 100 draf per pembuat tetap berlaku.

Salinan soal berasal dari isi draf terkini atau snapshot bila sudah dikirim. Setiap soal/pilihan mendapat ID baru, versi mulai 1, dan kepemilikan anak tujuan; jawaban, nilai, attempt, snapshot pengiriman dan jadwal tidak disalin. Salinan berstatus draf dengan revisi 0, bukan otomatis terkirim. Revisi sumber menolak formulir lama; token idempotensi mencegah pengiriman ulang membuat salinan ganda. Audit hanya mencatat identitas sumber/tujuan dan revisi, bukan teks privat. Tes wajib mencakup lintas keluarga/peran, hak paket, tautan sumber/tujuan, snapshot, perubahan salinan yang tidak mengubah sumber, CSRF, replay, batas kapasitas, dan kegagalan tanpa salinan parsial.

Pemeriksaan baca-saja pada `finance/application` (15 Oktober 2026) menemukan referensi Midtrans di model dan tampilan pengaturan self order/online food, tetapi tidak menemukan SDK Midtrans, endpoint Snap/API, URL API Midtrans, atau handler notifikasi di source PHP yang diperiksa. Karena itu, pengaturan yang ada belum cukup sebagai bukti alur pembayaran dapat dipakai ulang untuk Study. Sebelum integrasi dibangun, tunjukkan/konfirmasi modul aktif dan pemilik konfigurasi kredensial sandbox; jangan menyalin rahasia dari database/file Finance atau menganggap flag pengaturan sebagai validasi callback. Pemeriksaan ini tidak mengubah proyek Finance dan tidak membuat transaksi.

### Mini-game pertama: Cocokkan Pasangan

Latihan satu pemain memakai pasangan sisi depan/belakang flashcard terbit yang memang dapat dibaca peserta. Tujuannya melatih asosiasi istilah, arti, atau fakta; bukan ujian/sertifikasi. Satu babak maksimal empat pasangan untuk usia dini dan enam untuk kelompok lain, tanpa timer, suara otomatis, atau hukuman. Semua kartu yang memenuhi syarat dibagi dalam babak dengan minimal dua pasangan. Kartu dengan teks kosong/lebih dari 160 karakter atau sisi yang ambigu/duplikat setelah normalisasi spasi/huruf tidak dipakai; kartu aslinya tetap tersedia untuk dibaca.

Pilih satu kartu dari kolom kiri dan satu pasangan dari kanan, melalui sentuhan/klik atau Tab+Enter/Spasi. Pasangan benar ditandai dengan teks/simbol, salah memberi ajakan mencoba lagi; tersedia ulang dan lanjut babak. Pengacakan hanya untuk latihan, bukan kontrol ujian. Progres babak hanya di halaman saat ini, hilang saat muat ulang, tidak disimpan sebagai nilai/penguasaan resmi dan tidak memberi XP/lencana/kredit. Tidak ada endpoint penulisan game, sehingga manipulasi skor browser/replay/multi-tab tidak dapat memberi reward atau mengubah saldo/progres. Ini tidak menggantikan penilaian server untuk game yang kelak memberi reward. Akses materi tetap diperiksa server pada setiap pembukaan; salinan isi yang sudah dibaca browser tidak dapat ditarik kembali. Jika JavaScript mati, peserta dapat membaca pasangan sebagai alternatif.

Kriteria penerimaan: draf/arsip/akses berbayar yang tertutup tidak membocorkan kartu; POST ditolak; konten di-escape; kelompok usia menentukan ukuran babak; pasangan ambigu disaring; benar/salah/klik ulang/ulang/babak akhir bekerja tanpa skor ganda; keyboard dan reduced motion didukung; viewport 360/768/1280 diperiksa; tidak ada mutasi progres/wallet/audit saat bermain. Harga, konten nyata, XP dan rilis publik tetap memerlukan keputusan terpisah.

### Permainan tersimpan — alur peserta

Mode tersimpan menambah run milik peserta, snapshot kartu/aturan/urutan babak saat mulai, dan log pilihan pasangan. Satu run aktif per peserta/pelajaran; mulai memakai key idempotensi. Setiap pilihan dua kartu dinilai server berdasarkan babak aktif, disimpan atomik dengan revisi dan key permintaan. Key yang dikirim ulang dengan payload sama tidak menambah langkah, sedangkan payload berbeda atau revisi usang ditolak. Pasangan yang sudah cocok tidak dihitung ulang; seluruh pasangan harus selesai sebelum run selesai. Kartu sumber berubah tidak mengubah snapshot.

Catatan hasil berupa jumlah pasangan, pilihan yang dicoba, percobaan belum cocok, dan durasi dari mulai hingga selesai menurut jam server (termasuk waktu jeda, bukan waktu belajar aktif). Tidak ada nilai kelulusan, XP, kredit atau klaim anti-cheat ujian; isi pasangan tetap latihan yang boleh dibaca. Hak materi diperiksa ulang saat mulai/menyimpan dan saat membaca run aktif. Hasil selesai tetap milik peserta, run aktif berhenti menerima perubahan jika akses ditutup. Pembatalan menyimpan histori tanpa menghapus data; pengulangan membuat run baru. Batas teknis 10.000 pilihan per run mencegah log tidak terbatas, bukan kuota komersial.

Peserta dapat membuka mode tersimpan dari permainan lokal. Halaman awal menjelaskan pencatatan dan kebutuhan koneksi; jika ada run aktif, tampil tombol lanjutkan. Pilihan memakai kartu radio berlabel dan tombol Periksa pasangan. Formulir biasa tetap bekerja tanpa JavaScript, memakai CSRF, token tindakan bertanda tangan dan revisi, kemudian redirect 303 ke hasil server. Tidak ada nilai optimistis, autosave/offline, atau migrasi progres permainan lokal. Refresh membaca revisi terakhir; konflik tab menampilkan data terbaru tanpa menimpa. Beristirahat cukup meninggalkan halaman; menghentikan perlu halaman konfirmasi dan checkbox, dengan revisi agar formulir usang tidak membatalkan progres lebih baru. Catatan dihentikan tetap dapat dilihat, tetapi tidak dilanjutkan. Riwayat pribadi memakai pencarian judul literal, filter status, kartu responsif dan pagination 10 item. Hasil akhir tetap dapat dibaca saat kursus diarsipkan. Uji enam request-race lokal serta request/response dibuang sebelum/sesudah commit sudah tersedia. Peningkatan JavaScript memberi status pengiriman dan tautan pemulihan GET saat respons tidak pasti, tanpa retry otomatis. Chrome telah menguji offline sebelum pengiriman, respons hilang setelah 303, pemulihan tepat satu mutasi, serta fallback saat JavaScript diblokir. Kebijakan retensi, back-forward saat pengiriman, pengujian server target dan UAT masih perlu diselesaikan.

### Laporan permainan orang tua

Orang tua melihat laporan dari kartu anak pada dashboard. Akun orang tua, akun anak, serta tautannya wajib aktif; setiap query memeriksa ulang ketiganya. Semua orang tua yang memang tertaut aktif boleh melihat catatan permainan kursus anak tersebut. Ini tidak mengubah privasi soal latihan khusus milik pembuat sesi keluarga.

Ringkasan menghitung seluruh percobaan selesai/sedang bermain/dihentikan, bukan jumlah materi yang dikuasai. Filter judul/status dan pagination 10 item berlaku pada daftar; ringkasan seluruh histori diberi label jelas. Detail hanya memperlihatkan jumlah pasangan, pilihan, percobaan belum cocok, status dan waktu. Hasil aktif disebut sementara, permainan dihentikan tidak dianggap selesai, dan rentang waktu termasuk jeda bukan durasi belajar aktif. Laporan tidak membandingkan anak dan tidak memberi skor/XP/kredit.

Tidak ada isi kartu, log pilihan individual, token atau aksi mengubah permainan anak pada laporan. Orang tua juga tidak dapat memakai endpoint peserta dengan ID run anak. Histori tetap dapat dibaca saat kursus diarsipkan/akses paket habis, selama hubungan dan akun aktif. Revokasi menutup pembacaan berikutnya, bukan menghapus catatan. Kebijakan retensi tetap perlu keputusan terpisah sebelum pilot publik.
